= Java Software Engineer Interview Guide
:page-reading-assistant:
:page-subtitle: Every topic a Java backend interview covers, with a weightage out of 10, a study order, and a detailed page per topic with explanations, code and practice questions.
:page-difficulty: Medium
:page-tags: Java, Interview Preparation, Spring, Spring Boot
:page-revdate: 2026-11-11

This guide prepares you for a software engineer interview where Java is the main language.
It covers core Java, the JVM, concurrency, Spring and Spring Boot, persistence, security, microservices, testing, the coding round and the senior scenario round.
Each topic has its own page, and every page uses the same layout so you always know where to look.

The guide targets backend roles with roughly 0 to 8 years of experience.
Where expectations differ by level, the page says so.

== How to use this guide

. Read the <<topic-index,topic index>> and note the weightage of each topic.
. Study the topics in the order of the table. Earlier topics are prerequisites for later ones.
. On each page, read the concepts first, then answer the practice questions *aloud* before opening the answer.
. Mark the questions you could not answer in two minutes and revisit them two days later.
. Finish with the <<final-checklist,final checklist>> on the day before the interview.

TIP: Interviewers rarely stop at a definition.
After your first answer, expect "why?", "what happens under load?", "how would you test it?" and "how would you monitor it?".
Every page has a *Follow-ups to expect* section for this reason.

=== How the weightage was set

The scores are an editorial judgement, not measured data.
They come from comparing the topic lists and question banks of the sources in <<sources,Sources>> and from the attached handbook.
A few patterns were consistent across those sources:

* Java interview questions cluster around core Java and OOP, collections internals, concurrency, the JVM and Spring Boot.
* HashMap and ConcurrentHashMap internals are named as the most predictable topic for experienced candidates, which is why collections is the only 10.
* Modern Java features from Java 17 and 21 (records, sealed classes, pattern matching, virtual threads) now appear regularly, and many older question lists skip them.
* Spring Boot questions for experienced candidates focus on proxies, auto-configuration and transaction boundaries rather than annotation names.
* Senior interviews replace definitions with production scenarios: memory leaks, deadlocks and slow endpoints.

Adjust the scores for your target role.
A bank or service company tends to ask more core Java and Java 8 stream programs.
A product company tends to weigh the coding round and system design more.
A role that mentions LLMs or RAG raises Spring AI to about 8.

Pick the plan that matches the time you have.

|2 weeks
|Week 1: topics 1 to 6, plus 2 coding problems a day. Week 2: topics 7 to 12 and 15, plus 2 coding problems a day. Last two days: topic 16, mock interview, final checklist.

|Week 1: topics 1 to 4. Week 2: topics 5, 6 and 13. Week 3: topics 7 to 11. Week 4: topics 12, 15, 16 and 17 if relevant. Solve 3 coding problems a day throughout, and do one timed mock interview each weekend.

== Final checklist

Use this the day before the interview.

* [ ] I can explain each major concept in my own words, without a memorised one-line definition.
* [ ] For every "X versus Y" question, I can say when each one is the right choice.
* [ ] I know the time complexity of the main collection operations and of my coding solutions.
* [ ] I can state the thread-safety guarantees of the classes I mention.
* [ ] I can explain where a transaction starts and ends in my last project, and what happens on failure.
* [ ] I can write code without IDE auto-complete: a HashMap-based solution, a stream pipeline, a thread-safe class.
* [ ] I have two production incident stories and one architecture decision story ready (see xref:interview-guide/senior-scenarios.adoc[Production Scenarios]).
* [ ] I can discuss observability, security, testing, deployment and rollback for a service I built.
* [ ] I know which Java and Spring Boot versions my current project uses, and one feature from each that I have used.
