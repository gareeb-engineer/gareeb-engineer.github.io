Almost every Java interview includes a coding round, from a simple string program at a service company to two algorithm problems in 45 minutes at a product company.
This page focuses on doing it *in Java*: the APIs and idioms that make solutions short and correct, the common patterns, and worked solutions.
For the data structures themselves, see the xref:Data-Structure:index.adoc[Data Structure] section of this site.

== How to run the round

. *Clarify* (2 to 3 minutes). Restate the problem. Ask about input size, empty input, duplicates, negative numbers, character set (ASCII or Unicode), and whether to return indices or values.
. *Examples*. Walk through one normal and one edge case by hand.
. *Brute force first*. State it and its complexity in one sentence. It shows you can solve the problem at all.
. *Optimise*. Name the pattern (hash map, two pointers, sliding window, heap) and the new complexity before coding.
. *Code* cleanly with clear names. Talk while you write.
. *Test* by running your examples through the code by hand, then the edge cases.
. *Complexity*. State time and space at the end, and what you would change for larger inputs.

Interviewers grade communication and testing as well as correctness.
A clean, explained O(n log n) solution often scores better than a silent, buggy O(n) one.

== Complexity cheat sheet

[cols="2,2",options="header"]
|===
|Input size n |Target complexity

|n ≤ 10 |O(n!) or O(2ⁿ) backtracking is fine
|n ≤ 20 |O(2ⁿ)
|n ≤ 500 |O(n³)
|n ≤ 5,000 |O(n²)
|n ≤ 10⁶ |O(n log n) or O(n)
|n > 10⁸ |O(log n) or O(1)
|===

== Problem patterns

[cols="1,2,2",options="header"]
|===
|Pattern |Recognise it when |Examples

|Hash map / set |"Find a pair", "count", "seen before", "group by" |Two sum, anagram groups, first unique character
|Two pointers |Sorted array, pairs, palindromes, removing in place |Pair with sum in sorted array, container with most water, 3Sum
|Sliding window |Longest or shortest *contiguous* subarray or substring meeting a condition |Longest substring without repeats, max sum of size k
|Prefix sum |Range sums, subarray sum equals k |Subarray sum equals k (prefix sum + hash map)
|Binary search |Sorted data, or "minimum value that satisfies a monotonic condition" |Search in rotated array, first bad version, capacity to ship packages
|Stack |Matching brackets, "next greater element", undo |Valid parentheses, daily temperatures, min stack
|Heap |Top k, k-th largest, merge k sorted, scheduling |Top k frequent, k closest points, merge k lists
|BFS |Shortest path in unweighted graph or grid, level order |Number of islands, rotting oranges, word ladder
|DFS / backtracking |All combinations, permutations, paths, connected components |Subsets, permutations, N-Queens
|Dynamic programming |Optimal value, count of ways, overlapping sub-problems |Climbing stairs, coin change, longest common subsequence, knapsack
|Linked list pointers |In-place reversal, cycle, middle, merge |Reverse list, detect cycle, merge two sorted lists
|Intervals |Overlapping ranges |Merge intervals, meeting rooms
|===

== Worked solutions

[%collapsible]
.Two Sum: indices of two numbers that add up to a target.
====
Store each number's index in a map and look up the complement.
O(n) time, O(n) space.

[source,java]
----
static int[] twoSum(int[] nums, int target) {
    Map<Integer, Integer> indexOf = new HashMap<>();
    for (int i = 0; i < nums.length; i++) {
        Integer j = indexOf.get(target - nums[i]);
        if (j != null) return new int[]{j, i};
        indexOf.put(nums[i], i);
    }
    return new int[0];
}
----
====

[%collapsible]
.Valid parentheses.
====
Push expected closers; on a closer, it must match the top.
O(n) time and space.

[source,java]
----
static boolean isValid(String s) {
    Deque<Character> stack = new ArrayDeque<>();
    for (char c : s.toCharArray()) {
        switch (c) {
            case '(' -> stack.push(')');
            case '[' -> stack.push(']');
            case '{' -> stack.push('}');
            default -> { if (stack.isEmpty() || stack.pop() != c) return false; }
        }
    }
    return stack.isEmpty();
}
----
====

[%collapsible]
.Longest substring without repeating characters.
====
Sliding window: remember the last index of each character and move the left edge past a repeat.
O(n) time, O(alphabet) space.

[source,java]
----
static int longestUnique(String s) {
    Map<Character, Integer> last = new HashMap<>();
    int best = 0;
    for (int left = 0, right = 0; right < s.length(); right++) {
        char c = s.charAt(right);
        if (last.containsKey(c) && last.get(c) >= left) {
            left = last.get(c) + 1;
        }
        last.put(c, right);
        best = Math.max(best, right - left + 1);
    }
    return best;
}
----
====

[%collapsible]
.Top K frequent elements.
====
Count with a map, then keep a min-heap of size k by frequency.
O(n log k) time, O(n) space.
Mention bucket sort for O(n) if asked.

[source,java]
----
static List<Integer> topK(int[] nums, int k) {
    Map<Integer, Integer> count = new HashMap<>();
    for (int n : nums) count.merge(n, 1, Integer::sum);

    PriorityQueue<Map.Entry<Integer, Integer>> heap =
            new PriorityQueue<>(Map.Entry.comparingByValue());
    for (var e : count.entrySet()) {
        heap.offer(e);
        if (heap.size() > k) heap.poll();
    }
    List<Integer> result = new ArrayList<>();
    while (!heap.isEmpty()) result.add(heap.poll().getKey());
    Collections.reverse(result);
    return result;
}
----
====

[%collapsible]
.First non-repeated character.
====
Count while keeping insertion order, then return the first with count 1.
O(n) time.
For full Unicode, iterate code points (`s.codePoints()`) instead of ``char``s.

[source,java]
----
static Character firstUnique(String s) {
    Map<Character, Integer> count = new LinkedHashMap<>();
    for (char c : s.toCharArray()) count.merge(c, 1, Integer::sum);
    for (var e : count.entrySet()) {
        if (e.getValue() == 1) return e.getKey();
    }
    return null;
}
----

[%collapsible]
.Detect a cycle in a linked list (Floyd's algorithm).
====
A slow pointer moves one step, a fast pointer two.
If they meet, there is a cycle.
O(n) time, O(1) space.
To find the start of the cycle, reset one pointer to the head and move both one step until they meet.

[source,java]
----
static boolean hasCycle(ListNode head) {
    ListNode slow = head, fast = head;
    while (fast != null && fast.next != null) {
        slow = slow.next;
        fast = fast.next.next;
        if (slow == fast) return true;
    }
    return false;
}
----
====

[%collapsible]
.Reverse a linked list.
====
O(n) time, O(1) space.

[source,java]
----
static ListNode reverse(ListNode head) {
    ListNode prev = null, current = head;
    while (current != null) {
        ListNode next = current.next;
        current.next = prev;
        prev = current;
        current = next;
    }
    return prev;
}
----

[%collapsible]
.Merge overlapping intervals.
====
Sort by start, then extend or append.
O(n log n) time.

[source,java]
----
static int[][] merge(int[][] intervals) {
    Arrays.sort(intervals, Comparator.comparingInt(a -> a[0]));
    List<int[]> merged = new ArrayList<>();
    for (int[] in : intervals) {
        if (merged.isEmpty() || merged.getLast()[1] < in[0]) {
            merged.add(in);
        } else {
            merged.getLast()[1] = Math.max(merged.getLast()[1], in[1]);
        }
    }
    return merged.toArray(new int[0][]);
}
----
`getLast()` is Java 21 (sequenced collections); use `merged.get(merged.size() - 1)` on older versions.

[%collapsible]
.Binary search, including the first position of a target.
====
O(log n).

[source,java]
----
static int firstIndexOf(int[] a, int target) {
    int lo = 0, hi = a.length - 1, answer = -1;
    while (lo <= hi) {
        int mid = lo + (hi - lo) / 2;
        if (a[mid] >= target) {
            if (a[mid] == target) answer = mid;
            hi = mid - 1;                 // keep searching left
        } else {
            lo = mid + 1;
        }
    }
    return answer;
}
----

[%collapsible]
.Number of islands (grid BFS/DFS).
====
Each unvisited land cell starts a flood fill.
O(rows × cols) time.

[source,java]
----
static int islands(char[][] grid) {
    int count = 0;
    for (int r = 0; r < grid.length; r++) {
        for (int c = 0; c < grid[0].length; c++) {
            if (grid[r][c] == '1') {
                count++;
                sink(grid, r, c);
            }
        }
    }
    return count;
}

static void sink(char[][] g, int r, int c) {
    if (r < 0 || c < 0 || r >= g.length || c >= g[0].length || g[r][c] != '1') return;
    g[r][c] = '0';
    sink(g, r + 1, c); sink(g, r - 1, c); sink(g, r, c + 1); sink(g, r, c - 1);
}
----
For very large grids, use an explicit queue to avoid `StackOverflowError`.
====

[%collapsible]
.Subarray sum equals k.
====
Prefix sums plus a map of how many times each prefix sum occurred.
O(n).

[source,java]
----
static int subarraySum(int[] nums, int k) {
    Map<Integer, Integer> seen = new HashMap<>(Map.of(0, 1));
    int sum = 0, count = 0;
    for (int n : nums) {
        sum += n;
        count += seen.getOrDefault(sum - k, 0);
        seen.merge(sum, 1, Integer::sum);
    }
    return count;
}
----
====

[%collapsible]
.Coin change: minimum number of coins.
====
Bottom-up DP: `dp[a]` is the fewest coins for amount `a`.
O(amount × coins) time.

[source,java]
----
static int coinChange(int[] coins, int amount) {
    int[] dp = new int[amount + 1];
    Arrays.fill(dp, amount + 1);           // "infinity"
    dp[0] = 0;
    for (int a = 1; a <= amount; a++) {
        for (int coin : coins) {
            if (coin <= a) dp[a] = Math.min(dp[a], dp[a - coin] + 1);
        }
    }
    return dp[amount] > amount ? -1 : dp[amount];
}
----
====

[%collapsible]
.Group anagrams.
====
The sorted characters form the key.
O(n × m log m) for n words of length m.

[source,java]
----
static Collection<List<String>> groupAnagrams(String[] words) {
    Map<String, List<String>> groups = new HashMap<>();
    for (String w : words) {
        char[] chars = w.toCharArray();
        Arrays.sort(chars);
        groups.computeIfAbsent(new String(chars), k -> new ArrayList<>()).add(w);
    }
    return groups.values();
}
----

== Classic Java programs (service company rounds)

[%collapsible]
.Reverse a string without library reverse, and check a palindrome.
====
[source,java]
----
static String reverse(String s) {
    char[] c = s.toCharArray();
    for (int i = 0, j = c.length - 1; i < j; i++, j--) {
        char t = c[i]; c[i] = c[j]; c[j] = t;
    }
    return new String(c);
}

static boolean isPalindrome(String s) {
    int i = 0, j = s.length() - 1;
    while (i < j) {
        if (s.charAt(i++) != s.charAt(j--)) return false;
    }
    return true;
}
----

[%collapsible]
.Check whether a number is prime, and print primes up to n (sieve).
====
[source,java]
----
static boolean isPrime(int n) {
    if (n < 2) return false;
    for (int i = 2; (long) i * i <= n; i++) {
        if (n % i == 0) return false;
    }
    return true;
}

static List<Integer> primesUpTo(int n) {
    boolean[] composite = new boolean[n + 1];
    List<Integer> primes = new ArrayList<>();
    for (int i = 2; i <= n; i++) {
        if (!composite[i]) {
            primes.add(i);
            for (long j = (long) i * i; j <= n; j += i) composite[(int) j] = true;
        }
    }
    return primes;
}
----

[%collapsible]
.Fibonacci: recursive, memoised and iterative.
====
[source,java]
----
static long fibIterative(int n) {
    long a = 0, b = 1;
    for (int i = 0; i < n; i++) {
        long next = a + b;
        a = b;
        b = next;
    }
    return a;
}
----
Naive recursion is O(2ⁿ); memoisation and iteration are O(n).
See xref:Data-Structure:dynamic-programming/fibonacci-series.adoc[Fibonacci Series] for all versions.

[%collapsible]
.Find the missing number in 1..n.
====
[source,java]
----
static int missing(int[] nums, int n) {
    long expected = (long) n * (n + 1) / 2;
    long actual = 0;
    for (int x : nums) actual += x;
    return (int) (expected - actual);
}
----

== Machine-coding rounds

Some companies give 60 to 90 minutes to build a small working system: parking lot, elevator, splitwise, library management, rate limiter, LRU cache.
They grade class design, SOLID, extensibility, and working code over completeness.
The xref:Low-Level-Design:index.adoc[Low Level Design] section and its xref:Low-Level-Design:design-patterns.adoc[design patterns] page cover the approach.

== Common traps

* `a - b` in comparators.
* `(lo + hi) / 2` overflow.
* `int` overflow in products and sums: use `long`.
* Comparing `Integer` objects with `==` (works only from -128 to 127).
* Using `Stack` or `LinkedList` instead of `ArrayDeque`.
* Forgetting empty input and single-element input.
* Modifying a collection while iterating over it.
* Recursion too deep on large inputs.

== Follow-ups to expect

* "Can you do it in O(1) extra space?"
* "What if the input does not fit in memory?" (Streaming, external sort, partitioning by hash.)
* "What if this runs concurrently?"
* "Write tests for your function."
