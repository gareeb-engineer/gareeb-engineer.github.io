Java Software Engineer Interview Guide

Every topic a Java backend interview covers, with a weightage out of 10, a study order, and a detailed page per topic with explanations, code and practice questions.

  • Medium
  • Java
  • Interview Preparation
  • Spring
  • Spring Boot
~6 min read Updated Nov 11, 2026

This guide prepares you for a software engineer interview where Java is the main language. It covers core Java, the JVM, concurrency, Spring and Spring Boot, persistence, security, microservices, testing, the coding round and the senior scenario round. Each topic has its own page, and every page uses the same layout so you always know where to look.

The guide targets backend roles with roughly 0 to 8 years of experience. Where expectations differ by level, the page says so.

How to use this guide

  1. Read the topic index and note the weightage of each topic.

  2. Study the topics in the order of the table. Earlier topics are prerequisites for later ones.

  3. On each page, read the concepts first, then answer the practice questions aloud before opening the answer.

  4. Mark the questions you could not answer in two minutes and revisit them two days later.

  5. Finish with the final checklist on the day before the interview.

Interviewers rarely stop at a definition. After your first answer, expect "why?", "what happens under load?", "how would you test it?" and "how would you monitor it?". Every page has a Follow-ups to expect section for this reason.

Topic index and weightage

The weightage is a score out of 10 that combines two things: how often the topic comes up in Java backend interviews, and how much a weak answer hurts the overall result. A 10 means you will almost certainly be asked about it and a poor answer can end the interview. A 4 means it depends on the role.

How the weightage was set

The scores are an editorial judgement, not measured data. They come from comparing the topic lists and question banks of the sources in Sources and from the attached handbook. A few patterns were consistent across those sources:

  • Java interview questions cluster around core Java and OOP, collections internals, concurrency, the JVM and Spring Boot.

  • HashMap and ConcurrentHashMap internals are named as the most predictable topic for experienced candidates, which is why collections is the only 10.

  • Modern Java features from Java 17 and 21 (records, sealed classes, pattern matching, virtual threads) now appear regularly, and many older question lists skip them.

  • Spring Boot questions for experienced candidates focus on proxies, auto-configuration and transaction boundaries rather than annotation names.

  • Senior interviews replace definitions with production scenarios: memory leaks, deadlocks and slow endpoints.

Adjust the scores for your target role. A bank or service company tends to ask more core Java and Java 8 stream programs. A product company tends to weigh the coding round and system design more. A role that mentions LLMs or RAG raises Spring AI to about 8.

Study plans

Pick the plan that matches the time you have. Hours are estimates for someone who already writes Java at work.

Time available Plan

1 week (crash)

Days 1-2: topics 1, 2 and 3. Day 3: topics 5 and 7. Day 4: topics 8, 9 and 10. Day 5: topic 14, solve 10 problems. Day 6: topics 12 and 16. Day 7: practice questions only, then the final checklist.

2 weeks

Week 1: topics 1 to 6, plus 2 coding problems a day. Week 2: topics 7 to 12 and 15, plus 2 coding problems a day. Last two days: topic 16, mock interview, final checklist.

4 weeks

Week 1: topics 1 to 4. Week 2: topics 5, 6 and 13. Week 3: topics 7 to 11. Week 4: topics 12, 15, 16 and 17 if relevant. Solve 3 coding problems a day throughout, and do one timed mock interview each weekend.

The attached handbook

The file 9to5_Hustlers_Java_SpringBoot_Spring_AI_180_Interview_Questions_Designed.pdf in the repository root is used here as an extension. Its questions are mapped to the topic pages in the Handbook Qs column above, and each topic page covers those questions in its own words with added detail and code.

The handbook cover promises 180 questions, but the copy in this repository contains questions 1-120 (Java and Spring Boot) and 151-180 (Spring AI). Questions 121-150 are not in the file.

Final checklist

Use this the day before the interview.

  • I can explain each major concept in my own words, without a memorised one-line definition.

  • For every "X versus Y" question, I can say when each one is the right choice.

  • I know the time complexity of the main collection operations and of my coding solutions.

  • I can state the thread-safety guarantees of the classes I mention.

  • I can explain where a transaction starts and ends in my last project, and what happens on failure.

  • I can write code without IDE auto-complete: a HashMap-based solution, a stream pipeline, a thread-safe class.

  • I have two production incident stories and one architecture decision story ready (see Production Scenarios).

  • I can discuss observability, security, testing, deployment and rollback for a service I built.

  • I know which Java and Spring Boot versions my current project uses, and one feature from each that I have used.
